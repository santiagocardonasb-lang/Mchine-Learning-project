Saved model and preprocessing

  • Each training run serializes the fitted estimator with joblib and stores it in the model_runs table (the hosting disk is ephemeral), together with its parameters, metrics, training window and tercile cut points.
  • Preprocessing travels with the model: logistic regression is a scikit-learn pipeline with its fitted StandardScaler; the forest needs no scaling. Feature construction is the shared function ml/features.py::build_panel, used by training and by every prediction.
  • Inference reads the columns the model was trained with (feature_names_in_), so a model trained before a feature change keeps working until it is retrained.

User instructions

  1. Open the demo above, choose a zone to load real values, change them if you want and press Predict.
  2. Signed-in users can run Risk check for any UPZ from its stored reports, or press Check risk now on the map.
  3. Read the level together with its probability: a high level with a high probability means the zone should be visited first.
  4. Report anything that looks wrong from Help & feedback (question mark in the menu).

Integration into the information system

The model is part of the LocWaste information system developed in Activity 2:

  • Batch: every training run predicts all {{ ev.quality.zones.upz }} UPZ; results feed the risk layer of the map and the home page.
  • On demand: the risk check page and this demo; each prediction is logged with user, model version, result and duration.
  • Decision: high-risk UPZ become pending collection priorities that administrators schedule, complete or dismiss.
  • Lifecycle: retraining from the admin pages or automatically after {{ config.AUTO_RETRAIN_THRESHOLD }} new citizen reports.

Monitoring, incident reporting and user feedback

  • Monitoring: requests, response times, errors and inferences are logged automatically and shown at /admin/monitoring (phase 6).
  • Incidents: unhandled errors are recorded and replaced by a friendly page; users open an incident or bug ticket with the page attached.
  • Feedback: suggestion tickets; an administrator sets them in review and resolves them with an answer the user reads in My tickets.
